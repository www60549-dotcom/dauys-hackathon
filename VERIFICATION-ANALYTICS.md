# Аналитика Dauys: динамика, очередь и карта

Дата: 12 ноября 2026.

## Итоговое поведение

- После метрик основными блоками стали «Динамика обращений» и «Карта обращений».
- Нерелевантная большая диаграмма desktop/mobile и её синтетический набор удалены из проекта. На её месте — компактная «Как менялась очередь», ниже основного столбчатого графика, с высотой canvas 230 px на настольном экране и 215–240 px на узких экранах.
- Серии очереди: ожидающие команды и ожидающие ответа автора. Они восстановлены по истории статусов выбранных обращений на конец каждого интервала. Закрытые/решённые/отклонённые записи исключаются из открытой очереди; повторное открытие учитывается.
- Карта использует настоящую HTML-таблицу, кнопки ячеек и названий подразделений. Режимы «Все / Открытые / Просрочены» пересчитывают все числа в текущем срезе. В ячейках видны количество обращений, максимальный приоритет и отдельное число просрочек.
- Выбор ячейки открывает список всех подходящих обращений. Порядок: просроченные, открытые, затем по приоритету и давности. Список не теряет записи. Каждая строка открывает существующую карточку обращения. Есть переход к подразделению с самой большой открытой очередью.
- Нативный dialog сохраняет Escape, фокус и возврат к вызывающей кнопке; Tooltip сохраняет hover/focus/Escape. Календарь имеет горизонтальную прокрутку, чтобы ячейки на телефоне не сжимались в нечитаемые точки.

## Bklit Bar Chart

Источник: https://bklit.com/studio?s=v1.NrAMBoCICMEMCcC0BjAFggLpAuuYAmATgHYo54A6AGwFMBzGgOwBMdsg

Применён установленный навык Bklit, контекст получен через shadcn info. Через `npx shadcn@latest add @bklit/bar-chart --yes --overwrite` установлены официальные BarChart, Bar, BarXAxis и зависимости; свойства сверены с исходниками. Генератор изменил utils и тему: прикладные функции и изолированные токены восстановлены. Обновление официального chart-formatters сохранено для совместимости реестра. Новые npm-зависимости не понадобились.

Сохранены слои Grid, ReferenceArea, две серии Bar, обе числовые оси Y, BarXAxis и ChartTooltip. Не подключены Background, TrendLine и ChartLegend. Сохранены цвета var(--chart-1/2), round, fadedOpacity 0.3, groupGap 4, barGap 0.2 и все визуальные настройки справочной полосы. Tween 1.1 секунды и `[0.85,0,0.15,1]` передан явно в enterTransition.

Пользователь отдельно выбрал **визуал Bklit с реальными данными и осмысленной шкалой**. Поэтому desktop/mobile заменены на received/withSolution; диапазон 160–220 — на фактическую среднюю–пиковую нагрузку. Это адаптация, а не буквальная копия демонстрационных чисел Studio. Целочисленные подписи осей не предлагают считать дробные обращения; среднее при этом может быть дробным. Если среднее равно пику, полоса вырождается в один уровень, значения не увеличиваются искусственно.

Столбцы — группы обращений по дате создания. «Из них с решением» показывает текущую долю решённых в данной группе, а не количество событий решения в этом интервале. Принятые положительные отзывы не выдаются за решённые проблемы. При 7 днях — 7 интервалов; для более длинных периодов максимум 12, чтобы подписи не перегружали экран.

## Проверки

- npm test: 37 тестов проходят. Семь новых тестов проверяют сохранение всех 20 исходных записей в столбцах и фильтрах, правильный подсчёт решений, границы интервалов, восстановление статусов без переноса будущего состояния в прошлое, ожидание ответа, повторное открытие, пустые и многолетние срезы, режимы карты и сохранение/порядок всех записей в детализации.
- npm run build: строгий TypeScript и production-сборка проходят.
- Данные календаря, метрик, динамики и карты основаны на одном выбранном наборе обращений. Даты исходного датасета в MVP демонстрационные, история новых действий сохраняется локально.
- Графики загружаются отдельными lazy-модулями. Число точек динамики ограничено 12; приложение не добавляет постоянный кадровый цикл для аналитики.
- Визуальная сверка в браузере и проверка кликов на реальном устройстве не выполнялись: ранее доступ к локальному сайту для браузерной проверки был отклонён. Нативный dialog и переходы проверены по реализации; это не подмена проверки браузерного сценария.
- Сохраняется прежнее предупреждение сборки о размере блока Three.js; ошибок сборки нет.
