# Проверка выпуска — 13 ноября 2026

## Что изменилось

- Срок первого ответа отделён от срока решения. По умолчанию ответ ожидается
  за 18 часов. Реальный ответ исполнителя — комментарий или структурированный
  переход рабочего процесса; текст старой истории не интерпретируется.
- Напоминание доступно участникам просроченного обращения. Блокировка строки,
  исходная версия и интервал 24 часа защищают от параллельных и повторных нажатий.
  Ожидание уточнения автора приостанавливает эскалацию.
- Исполнитель и администраторы получают уведомление; событие пишется в историю
  атомарно. Администратор — явный резервный получатель, не выдуманный руководитель.
- Динамика показывает 12 календарных месяцев: создание по created_at, решения
  по структурированным переходам в resolved. Повторное подтверждение не считается
  вторым решением. Старые решения без достоверной даты показаны отдельной оговоркой.
- Текущий подтверждённый финансовый эффект считается по дате подтверждения;
  возврат проблемы снимает его, сохраняя историческое решение. Прогноз и цена
  ожидания не становятся подтверждённой экономией.
- Все аналитические агрегаты читаются в одном repeatable-read snapshot.
  Календарь Asia/Qyzylorda согласован с фильтрами списка. SSE учитывает общую
  транзакционную revision, поэтому обновляется и наблюдатель без личного уведомления.
- QR описывает работу через общую БД. Для локального LAN адрес задаётся API;
  опубликованный сайт использует свой origin. Защита сессии сохраняется.
- Ошибка загрузки lazy-модуля аналитики имеет явный экран повторной загрузки.
  Уточнён контраст текста причины отказа на мобильном экране.

## Проверка браузером

1. Создание проблемы, серверное назначение, сохранение цены ожидания 40 ч/мес.
   и 60 000 ₸/мес. как прогноза.
2. Запрос уточнения → SSE-обновление в другой сессии → ответ сотрудника.
3. План пилота 12 → 4 мин, запуск, запрет преждевременного решения, измерение
   4 мин, вывод и достижение цели.
4. Решение исполнителя → подтверждение автора → возврат с причиной. Версии 1–9.
5. Отдельное предложение → мотивированный отказ, причина видна автору.
6. Мобильный viewport 390×844: карточка и QR. SVG QR реально декодирован jsQR;
   декодированная ссылка совпала с действием «Проверить форму». Из новой вкладки
   по этой ссылке создано и сохранено обращение.

Артефакты и трасса находятся локально в data/output/playwright, логи API — в data/.

граница ошибки. Перезагрузка загружает новую сборку. Ожидаемый 401 /me гостя

## Пределы проверки

Обновление 13 ноября, утро: Docker Compose, общий образ Render и восстановление
backup проверены в Linux CI. Повторяемый локальный прогон: 175 API + 21 browser

Docker Engine на этом компьютере отсутствует: сборка образов и запуск Compose
здесь не проверены. Проверка выполнена на отдельном GitHub runner.

пары Compose volumes выполнено в отдельном CI-стенде. Физический телефон, Windows Firewall,
нагрузка и гарантированные 60 FPS не проверены. Браузерный мобильный viewport не
заменяет физический телефон.

GitHub подготовлен для передачи жюри. Vercel требует работающий публичный API;
финальный облачный статус фиксируется после проверки внешнего origin, а не по
факту наличия конфигурационных файлов.
