# Контракт первой интеграции

Типы wire DTO: `src/api/contracts.ts`. Преобразование в визуальные модели:
`src/api/adapters.ts`. Автоматическое согласование OpenAPI и генерация типов
остаются отдельной задачей перед стабилизацией production-контракта.

## Сессия

- `POST /api/login` — email/password, `{ok:true}`, HttpOnly session cookie.
- `GET /api/me` — id/name/email/role/department; 401 означает отсутствие входа.
- `POST /api/logout` — 204; cookie и серверная сессия отзываются.
- Токен не читается JavaScript и не сохраняется в localStorage.
- При выходе и 401 очищается кеш `workspace`, соединение SSE закрывается.

## Обращения

- Список: `{items,total,page,counts}`; размер страницы 30.
- Фильтры: q, status, kind, department, mine=true, assigned=true, page.
- status=active исключает closed/rejected, сохраняя resolved для подтверждения.
- sort=updated сортирует по updated_at; главная показывает свежие активные записи.
- counts.active считается сервером без текущего фильтра status.
- Создание: title/description/kind/category/department/priority/affected/expected_effect.
- Успешное создание: 201 `{id}`. Никаких клиентских ID для сохранённых записей.
- Полная карточка: `{appeal,comments,history,files,linked}`.
- Ответ комментария: 201 `Created`, он не обязан быть JSON.
- Автор подтверждает решение через PATCH `{status:"closed"}`.
- Исполнитель передаёт полную разрешённую структуру ManageAppealInput.
  Этот старый PATCH пока не является произвольным частичным merge.
- Редактирование текста автором доступно в new/waiting согласно правилам API.
- Новые команды, строгий автомат переходов и версии обращения — следующий этап.

## История и даты

Все даты API — RFC3339, в визуальных моделях — epoch milliseconds.
Старая история содержит action/name/created_at. Она отображается текстом с
нейтральным индикатором; статус из текста не восстанавливается.
Комментарии дополнены author_id; совпадающие имена не определяют права.

## Вложения

POST `/api/appeals/:id/files`, multipart field `file`, до 10 МиБ.
Загрузка выполняется в уже созданной карточке: её ошибка не создаёт новое обращение.
Скачивание: `/api/files/:id` с cookie. Content-Type multipart вручную не задаётся.

## Аналитика и SSE

Аналитика запрашивается отдельным серверным агрегатом, а не считается по странице.
Текущий trend — недельные когорты по созданию; withSolution — их текущий итог.
Переход к событийной месячной динамике и структурированной истории ещё не завершён.
Финансовый эффект API не конвертируется в часы без измерения и единиц.

SSE `/api/events`: именованное событие update, JSON `{revision}`.
Поток инвалидирует кеш, а данные повторно читаются из API. Собственные действия
тоже инвалидируют кеш. После reconnect выполняется сверка, даже при той же revision.
Существующий серверный polling уведомлений сохранён; общий event hub и гарантии
обновления глобальной аналитики для всех наблюдателей ещё требуют доработки.
