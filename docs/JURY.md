# Dauys: материал для жюри

## Задача

Сотрудник сообщает о проблеме или предлагает изменение, но сообщение часто
теряется в переписке. Dauys связывает обращение с ответственным, сроком,
обсуждением, проверкой результата и подтверждением автора.

## Что можно проверить

1. Сотрудник создаёт обращение; сервер назначает исполнителя по категории.
2. Исполнитель запрашивает уточнение; сотрудник отвечает в карточке.
3. Цена ожидания оценивает месячные потери времени. Это прогноз, а не экономия.
4. Пилот фиксирует baseline, цель, участников, срок и измеренный результат.
5. Исполнитель оформляет решение. Автор подтверждает его или возвращает проблему.
6. Отказ требует объяснения; благодарность обрабатывается отдельно от улучшений.
7. Просрочка допускает напоминание исполнителю и администраторам раз в 24 часа.
8. Аналитика считает решения по фактическим событиям за месяц, а не по дате
   создания исходного обращения; подтверждение не удваивает число решений.

## Отличия MVP

Цена ожидания помогает определить, какой проблемой заняться первой. Пилот
показывает, проверена ли гипотеза в работе. Возврат проблемы сохраняет предыдущее
решение и снимает текущий подтверждённый эффект. Поиск похожих обращений использует
объяснимые тематические правила; это не модель AI с заявленной точностью.

## Технологии

React 19, TypeScript, Vite, Tailwind CSS 4, Framer Motion, Three.js / R3F / Drei.
Go / Fiber, PostgreSQL 17, pgx / sqlc. HttpOnly-сессии, роли, защищённые вложения,
серверная пагинация и SSE. Модульный монолит; Redis и микросервисы не нужны текущему MVP.

## Проверка и запуск

Инструкция: [DEPLOYMENT.md](DEPLOYMENT.md). Compose собирает React и Go, запускает
PostgreSQL и Nginx, отдаёт приложение на одном порту. Для свежей локальной демо-БД
используются 20 синтетических исходных обращений A-001…A-020.
Демонстрационные дополнения и вычисленные оценки не являются фактами о компании.

Технический отчёт: [VERIFICATION-RELEASE.md](VERIFICATION-RELEASE.md).
CI проверяет сборки, unit-тесты, Docker Compose, общий образ и восстановление backup.
API и браузерные проверки выполнены на отдельной копии PostgreSQL.
Итоговая готовность: [SUBMISSION-CHECK.md](SUBMISSION-CHECK.md). Физический телефон
требует отдельной приёмки; мобильный viewport и сам QR проверены автоматически.

## Ограничения

Это работающий MVP, не завершённая корпоративная эксплуатация. Идемпотентные
ключи создания/файлов, измеренное нагрузочное тестирование, корпоративный bootstrap,
настройка иерархии руководителей и эксплуатационный мониторинг ещё нужны.
Бесплатный публичный стенд имеет ограничения провайдера; они описаны в инструкции.
