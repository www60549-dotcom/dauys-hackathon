# Приёмка Dauys по датасету хакатона

Матрица связывает сценарии раздела 4 исходного документа с экранами и проверками MVP. Проверка выполнена 11 ноября 2026 года. Основные сценарии реализованы; API-приёмка и регрессии проходят. Новые фильтры, аналитика и мотивированный отказ дополнительно проверены в настольном интерфейсе.

## Основа и границы

Источник — предоставленный «Датасет.docx»: 20 вымышленных обращений, 18 категорий, 9 проблем, 10 предложений и 1 положительный отзыв. Машиночитаемый снимок исходных текстов, ролей, статусов и примеров действий находится в `tests/dataset-source.json`. Начальные записи — `backend/cmd/server/seed.json`; все 20 текстов, категорий, типов, нормализованных статусов и приоритетов сверяются автоматически.

Обращения A-002, A-003, A-007, A-013 и A-014 содержат предложения о работе других систем. Dauys регистрирует их, назначает ответственного и сохраняет рассмотрение и результат. Подключение к реальным проектам, номенклатуре, бухгалтерским системам и планированию ресурсов в MVP не реализовано и для демонстрации исходного набора не требуется.

Сроки в фильтрах и отображении дат определены по `Asia/Qyzylorda` — времени Астаны UTC+5. Граница окончания включается до конца выбранного дня и не зависит от часового пояса сервера PostgreSQL.

Месяц создания в аналитике и переходе к списку считается по UTC; поле списка подписано явно. Фильтр месяца доски улучшений сохраняет прежнюю семантику месяца обновления результата.

## Результат проверки

- `node tests/dataset.mjs`: 28 PASS в финальном прогоне.
- `node tests/smoke.mjs`: 25 PASS.
- `node tests/dashboard.mjs`: 9 PASS.
- `node tests/features.mjs`: 26 PASS.
- Итого: **88 API-проверок**. Опциональный режим `FRESH_DATASET=1` добавляет проверку двух исходных первых ответов по 6 часов; его запускают только на нетронутой новой БД.
- Go: `go test ./...`, `go vet ./...`, сборка сервера. Svelte: проверка типов и production build.

API-приёмка выполнялась в отдельной БД `dauys_acceptance_20261111_v2`, API слушал только `127.0.0.1:8081`. Рабочая локальная БД `dauys` не сбрасывалась. Существующие пользовательские и тестовые записи сохранены. В рабочей БД две нетронутые начальные записи выровнены через штатный API: A-007 — высокий приоритет; A-008 — решено, без искусственного подтверждения и денежного эффекта. Обе корректировки отражены в истории.

## Воспроизведение

Запустите MVP. Из корня проекта выполните четыре команды тестов выше. По умолчанию они используют `http://localhost:5173`; переменная `BASE_URL` позволяет направить их на изолированный экземпляр. Скрипты создают синтетические записи, категории, комментарии и файлы; данные не удаляют. Для чистого показа используйте отдельно подготовленную новую БД, а для проверки сохранности — существующую без сброса.

## Ограничения проверки

Новый интерфейс проверен в настольном браузере. Проверка на реальном телефоне, чтение QR камерой, Lighthouse, k6, Linux/Docker и внешнее развёртывание в этот прогон не входят. Статусы и финансовые результаты — демонстрационные данные; полезность для реальной компании и нагрузочные показатели этим прогоном не доказаны. Состояния исходных обращений после действий пользователя могут отличаться от начального seed.
